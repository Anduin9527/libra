## 文档职责

本文将命令入口、状态管理、计算和输出拆到各命令自身的内部模块，使 Codex 与维护者能按职责定位和修改代码，同时保持现有 CLI、库调用和持久化语义。拆分是行为保持的结构变更；若发现现存缺陷，按 ER-10 建立独立修复卡，不夹带行为修复。

### 适用范围

- `src/command/{merge,worktree,status,diff,cloud,rebase}.rs` 及其同名子目录；保留原 `command::<name>` 路径、命令入口、参数类型和当前对其它命令开放的符号。
- 与移动代码直接相关的内联单元测试、`command_test` 既有命令套件，以及调用方编译契约。
- 每卡独立 review、测试、patch 发布和证据；最终全量收口。

### 非目标

- 不机械目录化其它命令；`fetch`、`push`、`maintenance` 按 `DEFER-CM-01` 重新评估。
- 不改 `src/cli.rs` 的命令注册或分发，不抽象统一命令框架，不改变 `src/internal/` 的所有权。
- 不调整 CLI flag、help、退出码、人读/JSON/porcelain 字节、错误码、网络协议、schema、序列化 sidecar 格式、锁/事务顺序、性能策略或用户文档中的兼容承诺。
- 不把已有 `#[cfg(test)]` 测试移走作为唯一成果；测试移动必须随同其生产职责所在卡完成。

### 成功定义

- 六个命令的入口文件仅承载参数、对外路径、分发及少量编排；大段实现进入按职责命名的私有子模块。最终每个受影响的单文件均低于 5,000 行；若出现一个职责无法在此阈值内自洽，先修订计划并经评审，而非为行数制造转发层。
- 既有 `crate::command::<name>::...` 调用路径、测试场景和各命令的输出、错误、状态写入与恢复行为保持；没有新增生产 `unwrap()`/`expect()`/`panic!()`。
- 每卡的代码和测试在本卡发布树上验收；全计划最终通过模板 ER-13/ER-14 全量门，Codex review 与 Claude Code 计划评审有字面 PASS 证据。

## 已决议设计决策

### ADR-CM-01: 保留原命令 module 路径

- **Status:** Accepted
- **Context:** `src/cli.rs`、其它命令和测试直接引用 `command::<name>` 中的类型或函数。
- **Decision:** 保留 `<name>.rs` 作为 facade，在 `<name>/` 增加私有子模块；旧可见路径由原位置或限定可见性的 re-export 维持。现有 `merge/signing.rs`、`diff/options.rs` 不改名。`worktree.rs` 被 `worktree-fuse.rs::legacy` 二次加载，新增子模块必须用显式 `#[path = "worktree/<file>.rs"]` 声明并核对两种 feature 编译及 `worktree-fuse.rs` 的 re-export。只为真实复用开放 `pub(crate)`，其余用私有或 `pub(super)`。
- **Alternatives considered:** 全部改为 `<name>/mod.rs` 会增加路径重命名和 review 噪声；跨命令公共框架会扩大范围。
- **Consequences:** 同命令卡都需编辑 facade，必须串行；新子模块仍要有清楚的所有权，不允许循环依赖。
- **Revisit when:** 明确的多命令消费者要求抽到 `src/internal/`，且有独立设计与测试。

### ADR-CM-02: 每个切片保持行为等价

- **Status:** Accepted
- **Context:** 结构重组跨越 refs、index、worktree、网络备份和 sidecar 等高风险路径。
- **Decision:** 每卡只移动现有逻辑、导入、可见性和相应测试；保持序列化字段、调用先后、错误映射、日志、CLI 文本、JSON schema 与退出码。若移动暴露现有 bug，先以 FIX 卡证明和修复，原卡不夹带语义变更。
- **Alternatives considered:** 边拆边统一错误/状态抽象会令行为差异难以归因。
- **Consequences:** 某些旧逻辑即使不理想也暂时保留；以明确测试和后续计划处理改进。
- **Revisit when:** 现有实现无法在保持外部契约的条件下编译，须先修订计划与卡范围。

## 全局工程约束

继承模板 `GC-01..GC-13`，另补本计划约束：

- **GC-CM-01 来源与输出冻结:** 每卡开始时记录受影响的旧符号、旧路径、既有单测/集成测试和 CLI 输出类型；拆分后对照。不得因 rustfmt、可见性或 re-export 移动而静默改变公开 API。
- **GC-CM-02 模块深度:** 子模块必须拥有完整职责，至少含生产决策或状态不变量；禁止仅转发一个调用的空壳文件和同一状态的双事实源。入口模块保留参数、分发、错误到 CLI 的映射和必要 re-export。
- **GC-CM-03 写集保护:** 当前 checkout 已有无关工作。每卡执行 `libra status --short --branch`、`libra diff -- <目标路径>`；目标路径若被其它在跑任务占用，则等待其独立提交/交接并重取基线。只精确暂存本卡写集，不用 `commit -a`。
- **GC-CM-04 性能与隐私:** 结构移动不得增加热路径对象加载、DB/网络调用、扫描或 secret 输出；cloud 恢复与 GC/状态类命令保持 fail-closed。
- **GC-CM-05 扫描门、serial 登记与锚点:** 每卡检查 `rg -l 'include_str!|src/command/(merge|worktree|status|diff|cloud|rebase)\.rs' tests` 定位直接读源码的测试及 TSV 数据文件（定位命令，不作通过证据），将受影响测试的扫描集合扩至原入口与实际新增子模块，既检查必须存在的符号，也扫描禁止模式；不得把旧文件留一条无效字符串骗过守卫。源内单测默认保留在原入口；CM-03 是唯一计划内迁移源内单测的卡，须同卡更新 `tests/SRC_SERIAL_CENSUS.tsv` 和 `tests/SRC_SERIAL_REGISTRY.tsv` 的 file+fn 路径，并运行 `SERIAL_CLASSIFY_TREE=src sh tests/SERIAL_CLASSIFY.sh` 与 `compat_serial_registry`。对本计划六个命令原路径及新增子目录的 census 行（含 helper 与注释邻近项），先检查文件存在且含对应 `fn <name>(`，然后仅对真正的 test 执行 lane 判定；该范围内 registry 的 file+fn 必须是真实 test。两类存在性检查都要在原守卫的 `touches == none` 跳过前进行，不扩大为无关命令历史 census 清理。其它卡如确须移动源内单测，先按 G-09 修订该卡写集、与 CM-03 的 TSV 顺序边及具名测试门，再开工。新增/重命名 compat target 同卡维护 `Cargo.toml`、`tests/compat/README.md`、`tests/INDEX.md`。移动符号后由单一发布者在 `plan-status.md` 同卡状态记录中列出旧→新路径映射，供开放计划执行者刷新行锚点；历史完成计划不批量重写。
