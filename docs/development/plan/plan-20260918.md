## 文档职责

本文把 `libra add` 在 libra-testcases `libra-0.22.19` 对照与后续 issue 计划中确认的问题收成**一份日期计划**。做法是：从现有 issue 计划**抽出**只服务 `add` 的任务卡，迁入本文；抽出后不再剩任务的 issue 计划整份删除；抽出后仍有其它命令任务的计划留下，并改为依赖本计划。

### ADR-CH-05: 空 pathspec 的 `--chmod`（TC-0053/0054）

- **Status:** Accepted
- **Context:** Git 的 `add --chmod=+x`（无 pathspec）exit 0、索引不变。Libra 走「nothing specified, nothing added」（129）。
- **Decision:**
  1. 当 `--chmod` 存在且 pathspec 为空、且不是 `-A`/`-u`/`--refresh`/`--renormalize`/`--resolved` 时，视为成功无操作：exit 0，不写索引，不写对象。
  2. `--chmod` 与非空 pathspec 仍按 CH-01。
  3. `--chmod` 与 `-p`/`--edit`/`--interactive` 的组合由 PSF-03 / 477 的隐藏入口处理；本卡不开放这些组合。
- **Alternatives considered:** 继续报用法错误并登记有意差异——TC-0053/0054 会失败，拒绝。
- **Consequences:** `add.rs:864-874` 的空 pathspec 门增加 `--chmod` 例外。
- **Revisit when:** Git 改变无 pathspec `--chmod` 语义。

### ADR-PSF-01: `--pathspec-from-file` 的 stdin 与分隔

- **Status:** Accepted
- **Context:** TC-0056、0058–0062。Git 把文件名 `-` 当作 stdin；默认按行（接受 LF 与 CRLF）；`--pathspec-file-nul` 按 NUL。
- **Decision:**
  1. 值为 `-` 时从 stdin 读字节，不打开名为 `-` 的仓库文件。
  2. `--pathspec-file-nul`：按 `0` 分割，不去掉 CR。
  3. 否则：按 `\n` 分割，并去掉行尾 `\r`。
  4. 解码失败（非 UTF-8）→ 128 + `LBR-IO-001`，零写入。
  5. 读完后的 pathspec 列表交给既有 `run_add`；空列表按 CH-02 / 既有空 pathspec 规则。
- **Alternatives considered:** 把 `-` 当作字面路径——与 Git 和 TC-0056 冲突，拒绝。
- **Consequences:** `execute_safe` 不再无条件 `fs::read`。
- **Revisit when:** 需要从 FIFO / 非 seekable 源做二次读取。

### ADR-PSF-02: C-quote 解码

- **Status:** Accepted
- **Context:** Git 在非 `-z` 的 `--pathspec-from-file` 上解码 C-style quoted 路径（`"..."`、`\n`、`\t`、八进制）。
- **Decision:**
  1. 仅非 NUL 模式做 C-quote 解码；NUL 模式保持字面。
  2. 复用仓库内已有 quote 解码（`utils::text` / path 输出的逆操作）；禁止在 `add.rs` 再写一套。
  3. 未闭合引号 → 128，可操作文案，零写入。
- **Alternatives considered:** 只 trim、不解码——TC-0064 类用例失败，拒绝。
- **Consequences:** 共享 helper，PSF-02 若改 `utils/` 则命中 T-1。
- **Revisit when:** 其它命令的 `--pathspec-from-file` 需要对齐。

### ADR-PSF-03: 与交互选项互斥、`--edit` 仍拒绝

- **Status:** Accepted
- **Context:** TC-0065。Git 禁止 `--pathspec-from-file` 与 `--interactive` / `--patch` / `--edit` 同时出现。Libra 的 `--edit` / `--interactive` 仍未实现；`-p` 由 477 HF-19 公开。
- **Decision:**
  1. `--pathspec-from-file` 与 `-p/--patch`、`--edit`、`--interactive` 互斥：129 + `LBR-CLI-002`，文案对齐 Git `cannot be used together`。
  2. `--edit`、`--interactive`、`add -i` 本身仍按 477 DEFER-01 / HF-14 拒绝或诊断；本卡只加与 from-file 的组合门。
  3. 命令行 pathspec 与 `--pathspec-from-file` 同时出现时，行为以 git 2.54 实跑为准写回 M-PSF（开工重核）；不得静默丢弃一侧。
- **Alternatives considered:** 等 `add -i` 全部实现再加互斥——from-file 用例会继续失败，拒绝。
- **Consequences:** 组合门在 clap 或 `execute_safe` 最前。
- **Revisit when:** `add --edit` 被排期。

### ADR-IA-01: Git 语义参照与判据矩阵

- **Status:** Accepted
- **Context:** issue 评论明确「措辞不必逐字节一致」，但退出状态、stdout 报告、stderr ignored 识别与 index 状态必须一致；issue 正文的建议与 Git 实际行为有出入。
- **Decision:** 以 git@`1630431f32` 源码（事实基线逐行锚定）与 `/usr/bin/git` 2.54 实跑为准。开工时每一行都要在相同 fixture 上用 git 复跑，并把 sanitized 对照写入 `LIBRA_TEST_SCRATCH_DIR`。自动化测试不调用系统 git。下列矩阵是 AC 引用的**判据规范**，每行必须有对应测试。

  通用 fixture：`.libraignore` 含 `*.log`、`!keep.log`、`build/`、`ignored-file`；`sub/.libraignore` 含 `local.tmp`；`.gitignore` 含 `gi.txt`；已跟踪 `track-this` 在工作区被修改；未跟踪 `other.txt`；目录 `dir/` 含未跟踪 `new.txt` 与被忽略的 `inner.log`。

  **M-EXIT（ignored 报告的退出状态，IA-01）** — 另有存在且被忽略的 `top.log`、`sub/local.tmp`

  | 行 | 调用 | Git 2.54 | Libra 目标 |
  |---|---|---|---|
  | E1 | `add other.txt top.log` | 1；`other.txt` 已暂存 | exit 1；`other.txt` 已暂存；`top.log` 未暂存 |
  | E2 | `add -n other.txt top.log` | 1；stdout `add 'other.txt'` | exit 1；stdout 报告 `other.txt`；index 不变 |
  | E3 | `add top.log`、`add -n top.log` | 1 | 保持 `LBR-ADD-001`，exit 128（ADR-IA-02） |
  | E4 | `add -n dir` | 0；不报告 `inner.log` | exit 0；不报告 |
  | E5 | `add -n .` | 0 | exit 0 |
  | E6 | `add -n -A`、`add -n -u` | 0 | exit 0 |
  | E7 | `add -f -n other.txt top.log` | 0 | exit 0；无 ignored 块 |
  | E8 | `add --ignore-errors other.txt top.log` | 1 | exit 1；`other.txt` 已暂存 |
  | E9 | `--json add -n other.txt top.log` | — | stdout 为既有 data envelope（`added`/`modified` 含 `other.txt`，`ignored:["top.log"]`）；exit 1；stderr 无人读块 |
  | E10 | `--exit-code-on-warning add -n other.txt top.log` | — | exit 1（优先于 9） |
  | E11 | 在 `sub/` 下运行 `add -n local.tmp ../other.txt` | 1 | exit 1；ignored 块列出该路径（拼写见 DEFER-02） |

  **M-OUT（人读 ignored 块，IA-01）**

  | 行 | 条件 | Libra 目标 |
  |---|---|---|
  | O1 | 混合形态 | stderr：标题行 `warning: the following paths are ignored by configured ignore rules:`、每行一个路径、`Hint: use -f if you really want to add them.` |
  | O2 | 任意 ignored 块 | 不再输出 `Hint: use 'libra restore --staged <file>' to unstage if needed` |

### ADR-IA-02: 退出状态模型

- **Status:** Accepted
- **Context:** Git 在 ignored 报告非空时以 1 结束，但仍完成其余路径（`builtin/add.c:346-357`）。Libra 的稳定错误码表只有 0/9/128/129 这几类粗粒度退出码，但已有「完整渲染后 `silent_exit(1)`」的先例（`check_ignore.rs:163-171`、`status.rs:4522-4523`）。
- **Decision:**
  1. `run_add` 的返回值与错误语义不变。退出决策只在 `execute_safe` 中做：完成 `render_add_output`、warning 记录与 `VCS_EVENT_POST_ADD` 分发之后，若 `result.ignored` 非空，就返回 `CliError::silent_exit(1)`。
  2. 「仅 ignored」形态仍由 `check_ignored_only_error` 返回 `LBR-ADD-001`，exit 128，保持 `add_json_test.rs:344-358` 的契约。
  3. `--json` / `--machine` 下 stdout 为既有 data envelope（结构不变），退出码为 1。
  4. exit 1 优先于 `--exit-code-on-warning` 的 9。「不被 ignore 的缺失 pathspec」仍只是 warning（exit 0，或在 `--exit-code-on-warning` 下为 9）。
  5. `-f` 时 ignored 列表为空，不触发。
- **Alternatives considered:** 为混合形态新增 128 类稳定错误码——error envelope 会丢失 `added`/`modified` 数据，且偏离 Git 的 1，拒绝。把决策放进 `run_add`——`rerere` 等内部调用方会在含 ignored 路径时中断，拒绝。把「仅 ignored」一并改为 exit 1——会破坏已发布的 `LBR-ADD-001` 契约，而上游测试只要求非零，拒绝。
- **Consequences:** 混合形态是一次公开行为变化（0 → 1），必须在 EN/zh 文档的退出状态说明、`COMPATIBILITY.md` 的 `add` 行与 dev 文档中写明。JSON 消费者应以 `data.ignored` 非空或退出码为判据。
- **Revisit when:** Libra 引入统一的「部分成功」退出码或 envelope 字段。

### ADR-IA-03: `--ignore-missing` 缺失路径的 ignore 判定

- **Status:** Accepted
- **Context:** GAP-02、GAP-06。Git 对 GLOB/ICASE magic 或不存在的路径，用 pathspec 的 match 字符串（已去除 magic、已加前缀）调用 `is_excluded`，命中才列入 ignored（`builtin/add.c:622-650`）。
- **Decision:**
  1. 在 `src/utils/pathspec/mod.rs` 新增只读访问器，按原始 spec 返回规范化后的仓库相对 match 路径（去除 magic、应用当前目录前缀、保留 icase 属性）；不改变任何匹配语义。
  2. `validate_pathspecs` 增加 `force` 参数。对「selectable 与 ignored 候选都不匹配」的 spec，在 `ignore_missing && !force` 时，用 `utils::ignore::should_ignore(path, IgnorePolicy::Respect, index)` 判定该 match 路径：命中 → 进入 `ignored`（沿用原始 spec 拼写）；未命中 → 进入 `missing`（保留既有 warning 与 JSON `missing`）。
  3. 含通配符但不带 magic 的 spec（如 `ign*`），按 Git 行为把字面字符串交给判定，结果以 M-MISS M11 的实跑为准。
- **Alternatives considered:** 在 `add.rs` 内另写一套 ignore 匹配——违反 GC-02，拒绝。直接调用 `check-ignore` 的 `classify_path`——它是命令私有函数，且带输出结构，拒绝。
- **Consequences:** `src/utils/pathspec/` 新增公共访问器，是共享 helper（IA-02 命中 T-1）。
- **Revisit when:** DEFER-02（路径拼写对齐 Git）被排期。

### ADR-IA-04: 有意差异

- **Status:** Accepted
- **Context:** issue 评论允许 Libra 措辞、额外 hint、错误码与 JSON 不同；以下差异仍需让用户知情。
- **Decision:** 下列差异同时写入 EN 文档、zh-CN 文档、`COMPATIBILITY.md` 的 `add` 行与 `docs/development/commands/add.md`：
  1. 「仅 ignored」形态为 `LBR-ADD-001`，exit 128（Git 为 1）。
  2. ignored 块标题与 hint 为 Libra 措辞，无 Git advice 行，且不支持 `advice.addIgnoredFile`。
  3. ignored 路径使用原始 pathspec 拼写（Git 为仓库相对路径）。
  4. 不被 ignore 的缺失 pathspec 仍输出 Libra 跳过 warning（Git 静默）。
  5. 目录模式下已存在的被忽略父目录不额外列出（M-MISS M5）。
- **Alternatives considered:** 不登记——违反 GC-03，拒绝。
- **Consequences:** 移植用例断言退出状态、stdout 报告、stderr 是否识别路径与 index 状态，不断言措辞。
- **Revisit when:** DEFER-01/02 被排期。

### ADR-CH-01: 拒绝判定

- **Status:** Accepted
- **Context:** GAP-01/02；git `builtin/add.c:44-72`、`:681-682`，`read-cache.c:920-942`。
- **Decision:**
  1. `apply_chmod` 对每个 pathspec 命中的索引条目（stage 0）判定：
     - 条目模式不是普通文件（`mode & 0o170000 != 0o100000`，含 `120000` 与 `160000`）→ 记为拒绝，条目保持不变，继续处理其余条目；
     - 普通文件 → 沿用现有逻辑（已是目标模式则无操作；dry-run 下工作树缺失或为符号链接时跳过且不报错）。
  2. 真实模式下，判定发生在本次暂存完成之后（沿用现有调用顺序 `add.rs:811-821`），因此新暂存的符号链接或工作树类型变化的条目以暂存后的模式判定。
  3. dry-run 下判定使用当前索引（沿用 `add.rs:695-702`），不把未入索引的新路径计入。
  4. 被拒绝路径的记录格式为 `(path, '+'|'-')`。
- **Alternatives considered:** 按工作树文件类型判定——与 Git 不一致（实测 `swap` 的 dry-run 在 Git 中为 exit 0），拒绝。遇到第一个非普通条目即中止——Git 会继续更新其它路径（`t3700:490-498`），拒绝。
- **Consequences:** `apply_chmod` 的签名增加拒绝列表输出，供 issues/479 UI-03 复用。
- **Revisit when:** Libra 支持 index v3 扩展条目类型。

### ADR-CH-02: 退出状态与人读输出

- **Status:** Accepted
- **Context:** issue 要求常规非零退出、指出路径与 `+x`，不要求数值或措辞与 Git 相同。issues/484 ADR-IA-02 已为 `add` 选定「完整渲染后 `silent_exit(1)`」模型。
- **Decision:**
  1. 存在任何拒绝时，`execute_safe` 在保存 index（真实模式）、完成常规渲染与既有警告之后，向 stderr 逐行输出 `error: cannot chmod +x '<path>'`（或 `-x`，路径按既有输出的路径表示），然后返回 `CliError::silent_exit(1)`。
  2. 退出码 1 优先于 `--exit-code-on-warning` 的 9。
  3. `--quiet` 不抑制 stderr 错误行；`--ignore-errors` 不抑制拒绝。
  4. 退出决策不放进 `run_add`，内部调用方行为不变。
  5. 与 issues/484 IA-01 共用同一个「渲染后非零」决策 helper：先落地者引入，后落地者复用（DEP-CH-04）。
- **Alternatives considered:** 返回带稳定错误码的 `CliError`（128/129）——会丢失已渲染的暂存结果与 JSON 数据，且与 issues/484 的模型不一致，拒绝。退出码 255——Libra 退出码表没有 255，拒绝。
- **Consequences:** 与 Git 的 255 差异在文档与 `COMPATIBILITY.md` 登记。
- **Revisit when:** Libra 统一「部分成功」退出码。

### ADR-CH-03: JSON 输出

- **Status:** Accepted
- **Context:** GAP-03。现有 `failed` 字段表示 `--ignore-errors` 下失败的路径，语义为警告级（exit 0）。
- **Decision:**
  - `AddOutput` 新增可选字段 `chmod_rejected: [{ "path": string, "flip": "+x" | "-x" }]`（为空时不序列化），不复用 `failed`。
  - `--json` / `--machine` 下 stdout 为既有 data envelope（包含该字段），退出码 1，stderr 不输出人读错误行。
- **Alternatives considered:** 复用 `failed`——混淆 `--ignore-errors` 的警告语义，拒绝。
- **Consequences:** 字段只增不改，既有 JSON 消费者不受影响。
- **Revisit when:** DEFER-01 或其它部分成功语义需要统一字段。

### ADR-AU-03: `add -u` 的 pathspec 校验（#491）

- **Status:** Accepted
- **Context:** GAP-01；git `builtin/add.c:635-676`、`dir.c:637-673`。
- **Decision:**
  1. `-u` 模式（含 `--renormalize` 以外的 `-u` 调用）的可匹配候选集为索引已知路径（任意 stage）与已跟踪但工作树删除的路径；工作树中的未跟踪新文件不再算作匹配。
  2. 未匹配时报错：pathspec 在工作树与索引中都无匹配 → `pathspec '<p>' did not match any files`（现有文案）；只匹配到未跟踪文件 → `pathspec '<p>' did not match any file(s) known to the index`。
  3. 校验在任何暂存与预览输出之前完成；`-n` 下同样先失败、零输出（与 Git「先预览后报错」不同，登记为有意差异，换取原子性）。
  4. `--ignore-errors` 下跳过该校验，只暂存能匹配的路径（与 Git 一致）；stderr 行为以 M-UPD U6 实跑为准。
  5. 同一 pathspec 重复出现且其中一个已匹配时不报错（`dir.c:650-667` 的去重规则）。
- **Alternatives considered:** 暂存可匹配路径后再报错——违反 #491 验收 3「索引字节不变」，拒绝。
- **Consequences:** 改动集中在 `validate_pathspecs` 的候选集，与 484 IA-02 串行（DEP-AU-02）。
- **Revisit when:** 无。

### ADR-AU-04: 未合并条目的暂存（#493）

- **Status:** Accepted
- **Context:** GAP-02；git `read-cache.c:3904`、`:3987-4024`、`:4026`；未合并条目暂存真值。
- **Decision:**
  1. **索引不变量：** 任一路径写入 stage 0 时，同一事务内删除该路径的 stage 1–3；删除一个路径时删除全部 stage。实现为 `add` 暂存路径的单一 helper，`stage_a_file` 与删除分支都经过它。
  2. **候选集：** `add` 的变更计算把「只有冲突 stage 的路径」纳入：工作树存在 → 视为待暂存修改；工作树缺失 → 视为删除。`-u`、`-A`、`.` 与显式 pathspec 共用该候选集。
  3. **标记检查：** 普通 `add` 不检查冲突标记（Git 一致）；只有 `--resolved`（ADR-AU-08）检查。
  4. **不做 rename 配对：** `add` 的候选计算不进行 rename 检测（与 `t2200:203` 的意图一致）。
  5. **报告分类：** 解决的未合并路径在人读摘要与 JSON 中计入 `modified`，工作树缺失时计入 `removed`；不再报告为 `new file`。
  6. **范围：** 只修改 `add` 使用的变更计算入口；`status` 与 `commit -a` 共享的计算函数若需改动，按 GC-AU-03 保持其对未合并路径的既有显示（`UU`）不变。
- **Alternatives considered:** 在 git-internal 的 `Index::add` 中自动删除冲突 stage——改变所有下游写入方（merge 需要写入冲突 stage），拒绝。
- **Consequences:** 承接 plan-20260903 的 `FIX-MG06-CAND-01`；AU-02 命中 T-1（共享变更计算）。
- **Revisit when:** 无。

### ADR-AU-05: `add` 默认人读输出（#493）

- **Status:** Accepted（需用户评审）
- **Context:**
  - Git 的 `add` 除 `-v`、`-n` 外不向 stdout 输出；`t2200:228` 断言 stdout 为空。
  - Libra 把默认摘要行写入 stdout，并在 `docs/commands/add.md:191-212` 文档化；Agent 与脚本应使用 `--json`/`--machine`。
  - Libra 已有「stdout 为终端才启用」的先例（`src/utils/pager.rs:182-187`）。
- **Decision:**
  1. 默认模式下，只有 stdout 为终端时才输出摘要行；stdout 被重定向或为管道时不输出（与 Git 一致）。
  2. `-v`、`--dry-run` 属于用户显式请求的输出，任何情况下都输出现有内容。
  3. `--json`、`--machine`、`--quiet`、stderr 警告不受影响。
  4. 判定集中在 `render_add_output`，并提供测试可控的判定开关（与 `LIBRA_TEST` 分页器处理一致），不在各分支重复检查终端。
- **Alternatives considered:**
  - 始终静默，摘要只在 `-v` 下输出——完全对齐 Git，但去掉了交互用户已习惯的确认信息；作为备选，若用户评审选择它，只需把第 1 条改为「始终不输出」。
  - 保持现状并把 `t2200:203` 登记为有意差异——无法满足 #493 验收 1，拒绝。
- **Consequences:** 依赖默认摘要的既有集成测试需改为断言非终端静默或改用 `-v`/`--json`（ER-AU-02 统计并同批更新）；`add.md` 的 Human Output 小节改写。
- **Revisit when:** 其它命令（如 `rm`、`mv`）也需要统一「非终端静默」策略时。

### ADR-AU-06: 全局 `--literal-pathspecs`（#492，共享引擎）

- **Status:** Accepted
- **Context:** GAP-04；git `git.c:282-289`、`pathspec.c:257-300`、`Documentation/git.adoc:197-200`。
- **Decision:**
  1. **参数：** 在 `Cli` 新增 `--literal-pathspecs` 与 `--no-literal-pathspecs`，后者覆盖前者；`apply_global_runtime_flags` 每次调用都设置进程级字面模式状态（未指定时由环境变量决定），避免复用进程继承旧状态。
  2. **位置：** 与 Libra 其它全局参数一致使用 `global = true`，放在子命令之后也接受（Git 在子命令后报 129），登记为有意差异。
  3. **环境变量：** 读取 `GIT_LITERAL_PATHSPECS`，`1/true/yes/on` 为开启，`0/false/no/off` 与未设置为关闭；无法识别的值按关闭处理并输出一次 warning。命令行参数优先于环境变量。
  4. **引擎语义：** 字面模式开启时 `Pathspec::parse` 不解析 magic（`:(...)`、`:/`、`:!`、`:^` 均按字面路径），不做通配，使用前缀匹配；`--pathspec-from-file` 读入的路径同样适用。
  5. **范围：** 共享引擎的全部使用方自动生效（M-LIT L6）；引擎之外的命令由 AU-05 处理。
- **Alternatives considered:** 只为 `add` 实现——#492 验收 1 要求全局语义，且 Git 的 `log`/`status`/`grep` 同样生效，拒绝。在子命令之后报错以对齐 Git——与 Libra 全局参数惯例不一致，拒绝。
- **Consequences:** AU-04 命中 T-1（`src/cli.rs` 全局参数与共享引擎）。
- **Revisit when:** DEFER-01 排期。

### ADR-AU-08: `add --resolved`（#494）

- **Status:** Accepted
- **Context:** GAP-06；git@`1630431f32` `builtin/add.c:270`、`:392-452`、`:509-516`、`:527-529`、`merge-ll.c:503-526`、`parse-options.c:1538-1566`；`t2207`。git 2.54 尚无该参数。
- **Decision:**
  1. **参数：** 新增 `--resolved`；不要求 pathspec，给出 pathspec 时只处理匹配的路径。
  2. **收集：** 取索引中带冲突 stage 的路径（按 pathspec 过滤、去重）；没有则 exit 0 且零写入。
  3. **标记检查：** 对工作树中存在的普通文件逐行检查冲突标记（行首连续 7 个 `<`、`=`、`>` 或 `|`，其后为空白或行尾），遇到二进制内容停止；任一文件仍含标记时，列出全部这类路径并以 `LBR-CONFLICT-001` 失败，零写入。
  4. **暂存：** 通过 ADR-AU-04 的 helper：工作树缺失 → 删除全部 stage；存在 → 写入 stage 0 并删除冲突 stage。
  5. **互斥：** 与 `-u`、`-A` 同用时报 `options '-u/--update' and '--resolved' cannot be used together`（三项同用时使用 Git 的三项文案），`LBR-CLI-002`；与 `-p`/`--patch`（477 HF-16..HF-19 提供）同用时同样报用法错误（Git 中 patch 分支先执行、`--resolved` 被忽略，登记为有意差异）。
  6. **组合：** `--dry-run` 预览并执行标记检查；输出与 JSON 结构沿用 `add`（ADR-AU-05）。
- **Alternatives considered:** 登记为有意不支持——#494 验收 1 允许，但 pinned Git 已实现且语义清晰，拒绝。
- **Consequences:** `add.md` 与 `COMPATIBILITY.md:182` 新增说明；`conflict-marker-size` 属性延后（DEFER-04）。
- **Revisit when:** DEFER-04 排期。

### ADR-OI-02: 锁持有者元数据与诊断

- **Status:** Accepted
- **Context:** GAP-02；git `lockfile.c:90`、`:105`、`:141`、`:254-300` 以 pid 文件区分三种情形。Libra 的锁基于 `flock`，文件内容可在持有期间写入。
- **Decision:**
  1. 获取 generation 锁或分片锁成功后，截断并写入一行 JSON 元数据 `{pid, purpose, started_at_ms, invocation}`；`purpose` 取值 `marker_publication`、`queued_update`、`replay`、`deletion_fence`。写入失败不影响加锁（M-DIAG D6）。
  2. 超时后读取元数据（读上限 1 KiB）：pid 等于本进程 → D2；pid 存活 → D1；pid 不存在或元数据缺失、不可读 → D3。Windows 无法打开时走 D3。
  3. 所有文案追加 D4 说明。判定与文案集中在一个函数，替换 `client_storage.rs:299` 的固定文案，并更新钉住旧文案的测试（`:3316`）。
  4. 元数据不作为锁语义的一部分：释放锁时不清空内容，下一个持有者覆盖；读取方只把它当诊断线索。
- **Alternatives considered:** 另建 pid 侧车文件——需要额外原子写与清理，拒绝。改用 SQLite 记录持有者——锁与数据库连接生命周期不一致，拒绝。
- **Consequences:** 锁文件由零字节变为含一行元数据；锁命名空间规模不变。
- **Revisit when:** 锁实现更换。

### ADR-OI-03: 等待策略与只读预检回放

- **Status:** Accepted
- **Context:** GAP-03、GAP-04；git `lockfile.c:198-199`、`:206-251`；`Documentation/config/core.adoc:580-590`。
- **Decision:**
  1. 发布方与回放方的等待改为 1ms 起步二次退避加 ±25% 抖动，单次休眠上限 1 秒；非测试构建预算由 2 秒改为 10 秒，测试构建保持 100ms。
  2. `repair_pending_object_index_updates_before_command` 在 `require_complete=false` 的命令中使用非阻塞尝试获取 generation 锁；忙时本次跳过回放，不输出告警，只记 debug 日志。
  3. `require_complete=true` 的命令（`cloud sync`、破坏性 agent 清理等）保持阻塞等待，预算同第 1 条，失败时 fail-closed。
  4. 删除栅栏与回放持锁范围不变（保持与发布方的全序）。
- **Alternatives considered:** 新增配置键——需要配置文档与跨层读取，登记 DEFER-02。无限等待——卡死时用户无反馈，拒绝。
- **Consequences:** 慢速卷上写命令的最坏等待由 2 秒增至 10 秒，换取不失败。
- **Revisit when:** DEFER-02 排期。

### ADR-OI-04: 批量发布 repair marker

- **Status:** Accepted
- **Context:** GAP-05；issue 建议「每次调用只取一次锁」；git `builtin/add.c:531`、`:686-688` 整个调用只持有一次索引锁。
- **Decision:**
  1. `ClientStorage` 新增批量发布接口：调用方累积已存储对象的 `IndexUpdateMsg`，每满 256 个（或调用结束）在一次 generation 锁持有期间原子写入该批 marker，再逐个入队。
  2. `add`（经 `object_ext` 的 blob 保存路径）与操作日志快照的 blob/tree 写入改用批量接口；单对象 `put` 保持现有语义，内部等价于批大小 1。
  3. 语义不变式：每个 marker 在其消息入队前已持久化；删除栅栏与回放在批与批之间可以取得 generation 锁；批内失败时已写入的 marker 保留并返回错误（M-BATCH B2）。
  4. 批大小为常量，不暴露配置。
- **Alternatives considered:** 整个调用只取一次锁——长时间阻塞删除栅栏与其它进程，拒绝。调用开始先取锁、结束释放——同上，拒绝。
- **Consequences:** 发布路径命中 T-1；需要计数钩子（仅测试构建）断言锁获取次数。
- **Revisit when:** 锁实现更换。

### ADR-OI-05: `add` 在 marker 注册失败时的契约

- **Status:** Accepted
- **Context:** issue 后续第 4 项；R2′ 显示对象已写入而暂存区为空；git 在索引锁失败时同样整体失败且暂存区不变，已写入的松散对象保留。
- **Decision:**
  1. 保持原子失败：exit 128、`LBR-IO-002` 不变，暂存区不变。理由是 marker 未持久化时继续暂存会让云端目录遗漏对象，而 marker 正是回放的唯一持久记录。
  2. 文案改为单一前缀：说明对象负载已安全写入、未暂存任何路径、锁释放后直接重试即可且不会重复写入负载、无需删除锁文件；锁超时情形拼接 ADR-OI-02 的持有者说明。
  3. `--json` error envelope 的 `details` 增加 `stored_objects` 与 `staged`。
  4. 去除快照路径的双重前缀：`SnapshotError` 包装内层 facet 错误时不重复「capture failed」字样（`snapshot.rs:95`、`facet.rs:111`、`middleware.rs:681-687`）。
- **Alternatives considered:** marker 失败时照常暂存并告警——破坏云端目录的持久性保证，拒绝。改用 `LBR-CONFLICT-002`——改变已发布稳定码，收益不足，拒绝。
- **Consequences:** `add` 文档错误表与 commit/hash-object/update-index 文档同步文案说明。
- **Revisit when:** 云端目录改为不依赖本地 marker 的一致性模型。

### ADR-SW-04: 尊重语义（`core.sparseCheckout=false`）

- **Status:** Accepted
- **Context:** GAP-05/06；git `builtin/add.c:55-57`、`:599-658`，`dir.c:1612`（稀疏检出关闭时 `path_in_sparse_checkout` 视全部路径在内，只看索引位）。
- **Decision:**
  1. **status/diff：** `changes_to_be_staged_split_with_index` 对 skip-worktree 条目不产生工作树删除或修改（`status`、`diff`/`diff-files`、`add -u`/`-A`、`commit -a` 随之一致）。
  2. **add：** pathspec 只命中 skip-worktree 条目时（且未给 `--sparse`），把该 pathspec 记入稀疏列表，不暂存、不删除，继续处理其它 pathspec；结束时输出稀疏诊断并以非零退出。适用于 `--dry-run`、`--ignore-missing`、`--renormalize`、`--chmod`。
  3. **pathspec 同时命中稀疏与非稀疏条目**（`t3705` 的 `*_entry`）时不给诊断。
  4. **`--sparse`：** 允许更新 skip-worktree 条目并保留该位；文件缺失时行为与 Git 一致（exit 128/Libra 对应的 pathspec 不匹配错误）。
- **Alternatives considered:** 仅在 `add` 内特判——`status` 仍报告删除，`commit -a` 会删除条目，拒绝。
- **Consequences:** 变更计算为共享函数，SW-05 命中 T-1。
- **Revisit when:** D10 物化稀疏落地后需要结合模式匹配。

### ADR-SW-05: `add` 稀疏诊断与退出

- **Status:** Accepted
- **Context:** issue 允许产品化措辞；issues/484 ADR-IA-02、issues/489 ADR-CH-02 已为 `add` 选定「完整渲染后 `silent_exit(1)`」。
- **Decision:**
  - stderr 输出头部「The following paths and/or pathspecs matched paths that exist outside of your sparse-checkout definition, so will not be updated in the index:」，随后逐行输出 pathspec 原文，再输出 Libra 格式的 hint（使用 `--sparse`；或清除 skip-worktree 位 `libra update-index --no-skip-worktree <path>`）。
  - 退出码 1，复用共享的渲染后非零决策 helper。
  - JSON 新增可选字段 `sparse_paths: [string]`（为空不序列化），结构化模式下不输出人读诊断。
  - `advice.updateSparsePath` 不支持（DEFER-02）。
- **Alternatives considered:** 新增稳定错误码并返回 `CliError`——丢失已渲染结果，与 484/489 模型不一致，拒绝。
- **Consequences:** 与 Git 的 hint 行差异登记为有意差异。
- **Revisit when:** 引入 advice 配置体系。

### ADR-WT-05: intent-to-add 语义与依赖

- **Status:** Accepted
- **Context:** GAP-05..07；git `builtin/add.c:271`、`:568`，`read-cache.c:716-754`，`cache-tree.c:465-472`，`wt-status.c:755`，`diff-lib.c:264`、`:455`，`builtin/commit.c:1040-1046`；490 计划 ADR-SW-02 已规定 `Flags.intent_to_add` 与 v3 读写，ADR-SW-03 规定标志保留单一 helper。
- **Decision:**
  1. **索引表示：** intent-to-add 条目为 mode `100644`、空 blob、stage 0，并置 490 ADR-SW-02 的 `intent_to_add` 扩展位；本计划不另写索引解析。
  2. **保留规则：** 替换同路径条目时按 490 ADR-SW-03 的 helper 处理；`add <path>` 写入实际内容时显式清除该位；`reset`/`restore --staged` 以目标树重建条目，因路径不在目标树中而移除条目（与 490 的「重建不继承」语义一致）。
  3. **消费面：** status 与 diff 把该条目视为「工作树新增、索引无此路径」；写树与提交的空检查忽略该条目；`commit -a` 按普通已跟踪文件暂存其内容；`stash push` 遇到该条目拒绝；`rm --cached` 可移除。
  4. **公开节奏：** WT-05、WT-06 期间 `-N/--intent-to-add` 以 `hide = true` 注册且不写文档；WT-07 完成全部写入面后取消隐藏，避免中间版本把空 blob 写入提交。
- **Alternatives considered:** 用空 blob 但不设扩展位——无法区分真正的空文件，写树与提交语义错误，拒绝。等待 490 全部卡完成后再立计划——延长 issue 周期，且本计划可先完成其余 8 张卡，拒绝。
- **Consequences:** Phase 4 被 DEP-WT-01、DEP-WT-02 阻塞；490 计划 DEFER-05 由本计划承接。
- **Revisit when:** 490 ADR-SW-02 的 API 变化。

### ADR-FM-04: `core.fileMode`

- **Status:** Accepted
- **Context:** GAP-04；git `environment.c:327-328`、`:762`、`read-cache.c:755-769`；实测 F1、F2、D4/S10。
- **Decision:**
  1. 新增仓库配置读取 `core.fileMode`（大小写不敏感），经 `parse_git_bool` 解析；未设置时 Unix 为 `true`、非 Unix 为 `false`。
  2. 非法值 fail-closed：消息 `bad boolean config value '<v>' for 'core.filemode'`，错误码与退出码沿用 `commit.verbose` 非法布尔的既有映射（`src/command/commit.rs:899`），在任何写入前报告。
  3. `false` 时：`add`、`update-index <path>`、`commit -a` 暂存已有条目沿用原条目 mode，新文件为 `100644`；`status`、`diff`、`stash push` 不比较可执行位。
  4. `add --chmod` 与 `update-index --chmod`/`--cacheinfo` 不受影响。
- **Alternatives considered:** 忽略非法值——与 Git 不一致且掩盖配置错误，拒绝。
- **Consequences:** 配置读取为共享 helper，FM-03 命中 T-1。
- **Revisit when:** 支持 `core.symlinks=false`。

### ADR-FM-05: mode-only 工作树变化检测

- **Status:** Accepted
- **Context:** GAP-05；git `read-cache.c:316-324`；实测 D1–D6、S2。
- **Decision:**
  1. 在 `changes_to_be_staged_split_with_index` 中，对常规文件条目在 `core.fileMode=true` 时比较索引 mode 与工作树属主 `x` 位；不同即为 modified，即使 blob hash 相同。
  2. porcelain v2 的 `.M` 行与模式列、JSON `modified` 由同一变化集合产生。
  3. `add`、`commit -a` 暂存 mode-only 变化时更新索引条目 mode 与 stat；`stash push` 把 mode-only 变化视为本地修改并在 pop 时恢复 mode。
  4. `diff` 在 `core.fileMode=false` 时不输出 mode-only 差异。
  5. 与 490 计划 SW-05 的 skip-worktree 跳过规则同时成立：带 skip-worktree 位的条目不做 mode 比较。
- **Alternatives considered:** 只在 `diff` 保留检测——issue 期望 `status` 可见，拒绝。
- **Consequences:** `status` 输出在旧工作树上出现新的 ` M` 行，由 FM-05 缓解。
- **Revisit when:** 引入 fsmonitor/untracked cache。
