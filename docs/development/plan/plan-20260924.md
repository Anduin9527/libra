## 文檔職責

### 適用範圍

- 建立 provider-neutral 的 Agent Capture 協調層：validated ingress、純 lifecycle reducer、transcript snapshot、catalog/checkpoint store ports、coordinator 與 bounded finalizer。
- 把 `src/internal/ai/hooks/runtime.rs` 與 `src/internal/ai/agent_import.rs` 逐步改成薄入口；provider adapter 只負責來源探測、原生事件解析、原生 transcript 取得與能力投影。
- 保留既有 `ObservedAgent`、`HookProvider`、`LifecycleEvent`、`CaptureScope`、`TranscriptSource`、`RedactedBytes`、`TracesTxnExtra` 與 `refs/libra/traces` 契約，避免再造平行 wire/schema。
- 提供 OpenCode、Codex、Claude Code、Pi 後續計劃可共同使用的單一寫入路徑與 conformance gate。
- 新建計劃或推進任一 ACF 卡時，同一變更同步 [`plan-status.md`](plan-status.md)；計劃狀態或日期索引改變時同步 [`plan-long.md`](plan-long.md)。

### 非目標

- 不複製 Entire 原始碼；只借鑑其 agent / session / strategy / checkpoint 分層與契約測試方式。
- 不把 Entire 的 shadow branch、`entire/checkpoints/v1` 或 `refs/entire/checkpoints/<shard>/<id>` 搬進 Libra；Libra v1 仍寫 `refs/libra/traces`，per-checkpoint ref backend 另列 `DEFER-ACF-01`。
- 不改成永久保存未脫敏的完整 provider transcript。Libra 的 raw bytes 只可在已授權、具上限的記憶體/descriptor 邊界內存在；耐久 sink 仍只收 `RedactedBytes` 或 reasoning 計劃明定的 opaque artifact。
- 不在本計劃補齊 OpenCode/Codex/Claude/Pi 的 provider-specific event taxonomy、reasoning classifier、token/file extraction、installer 或 upstream version pin；它們仍由各 provider 計劃承接。
- 不新增公開 CLI 子命令、flag、JSON schema 或穩定錯誤碼；公開表面若在執行中成為必要，先修訂任務卡與文件影響後再開工。
- 不新增 SQLite schema。若 ACF-04/07 證明現有 `agent_session.state/metadata_json` 與 traces inflight marker 無法表達恢復狀態，先另立 migration 卡並按 GC-13 登記，不得在既有卡內順手加表。

### 成功定義

- provider-native payload 經單一入口變為已驗證、已作用域化的 capture command；provider adapter 不直接寫 SQL、session JSONL、Git object/ref 或 doctor 狀態。
- lifecycle transition 是純函數：輸入當前 typed state + normalized event，輸出 next state + bounded actions；重放同一 event id 不重複建立 checkpoint 或投影。
- live hook 與 historical import 共用 transcript snapshot、catalog store、checkpoint store；兩條路徑的 redaction、scope fence、容量上限、原子寫入與錯誤分類一致。
- SessionEnd/TurnEnd 的同步預算耗盡時留下可診斷且可重放的 pending finalize；不得以 exit 0 或 `stopped` 掩蓋 checkpoint 未落盤。
- OpenCode/Codex/Claude/Pi 計劃只新增 adapter/parser/projector/policy，不再各自擴張 shared `hooks/runtime.rs` 的 provider branch。
- ACF-01..ACF-09 全部 `done/complete`、最終 Claude review 為字面 `VERDICT: PASS`、ER-13 全量收口門全綠後，provider production 卡才解除各下游計劃鏡像的 `DEP-ACF-MIRROR`。

## 已決議設計決策

### ADR-ACF-01：四層架構，不新增第二套 provider framework

- **Status:** Accepted
- **Decision:** 固定 `Provider Adapter → Capture Coordinator/Reducer → Catalog/Checkpoint Store Ports → CLI/Hook/Import Entry` 四層。現有 `ObservedAgent`、`HookProvider`、`LifecycleEvent` 是 provider contract；新模組只接它們，不另建 `GenericAgent` 或另一 registry。
- **Consequence:** provider-specific module 不得依賴 SeaORM、`HistoryManager` 或 doctor internals。

### ADR-ACF-02：transition 是純函數，side effect 是 typed action

- **Status:** Accepted
- **Decision:** reducer 接受 durable capture state、validated event 與 policy，回傳 next state + `CaptureAction[]`；SQL/ref/transcript I/O 只在 coordinator 執行。unknown event 在 adapter 邊界 skip-and-log；非法 transition fail-closed，不靠 metadata key 猜測。
- **Consequence:** 同一 event id 重放只可產生相同 action key；store 以該 key 冪等。

### 對外契約 `CTR-ACF-DM06-v1`：可撤銷的 `agent_session` 終態

此契約由本計劃 owner 在 ACF-02 交付、ACF-08 對 live/import writer 重核；[`plan-20260923.md`](plan-20260923.md) DM-05 是 consumer。它是該計劃 `DEP-DM-06` 方案 (b) 的具名、版本化交付物，不把 Memory projection 反向變成本計劃的輸入。

| Predicate | v1 contract | Owner / evidence |
|---|---|---|
| terminal | 只有 `state='stopped' AND stopped_at IS NOT NULL` 的 session 是可消費終態 | reducer action + catalog mutation |
| explicit CLI resume | `libra agent session resume` 後 `state='active' AND stopped_at IS NULL`，且 `sync_revision` 嚴格增加 | 既有 `src/command/agent/session.rs` writer；不在 ACF production 寫集，以 ACF-02 integration contract test pin |
| live lifecycle reactivation | 任一非 `SessionEnd` live event 都離開 `stopped` 並增加 `sync_revision`：`Compaction` 進入 `condensed`，其餘事件進入 `active`；live upsert **不承諾**清空舊 `stopped_at`，consumer 必須按完整 terminal predicate 判定 | ACF-02 reducer + runtime adapter |
| import reactivation | historical transcript 出現較新非終態 activity 時，session 回到 `active`、清空舊 `stopped_at`，且 `sync_revision` 嚴格增加 | `src/internal/ai/coverage_gate.rs::merge_import_session_lifecycle` + ACF-08 `agent_import_test::import_reactivation_consumer_contract_v1` |

方案 (b) 只有在本計劃交付 `agent_lifecycle_event_test::{terminal_consumer_contract_v1,explicit_cli_resume_consumer_contract_v1}`，且 plan-20260923 登記 `memory_agent_session_test::stop_resume_reconciles_deletion` consumer gate 後可解除 DM-05；截止門沿用 `DEP-DM-06`：DM-04 `done/complete`。屆時任一交付缺失，方案 (b) 自動失效並回落方案 (a)：等待 ACF-08 `done/complete`，再重核上表四個 predicate。

### ADR-ACF-03：native bytes 只作 source，durable sink 延續 Libra privacy 契約

- **Status:** Accepted
- **Decision:** snapshot service 從 `TranscriptSource` 取得 provider-native bytes，先計算 source identity/digest，再依既有 redaction/reasoning policy 產生 durable payload。普通 transcript、metadata、event、log、error 不得含 raw secrets；opaque encrypted reasoning 仍由 RG 計劃管理。
- **Consequence:** 不照搬 Entire「每 checkpoint 永久保存完整 raw native transcript」；但不允許從 hook event 重建假 transcript。

### ADR-ACF-04：store port 必須保留 scope、transaction 與 repair 證據

- **Status:** Accepted
- **Decision:** `CaptureCatalogStore` 所有 mutable request 攜帶 `CaptureScope`/fence；`CaptureCheckpointStore` 接受 typed redacted snapshot、marker generation 與 `TracesTxnExtra`。port 不得把成功 ref CAS 與 catalog/coverage commit 拆成無法復原的兩次 success。
- **Consequence:** fake store 要模擬 conflict、stale generation、scope mismatch；不能只錄 happy path。

### ADR-ACF-05：先抽象 backend，不在本輪改 ref topology

- **Status:** Accepted
- **Decision:** ACF-05 以 request-oriented façade 包住既有 `refs/libra/traces`。per-checkpoint refs、ephemeral branch 或遠端 backend 不在本輪；store API 不暴露 branch-specific path，為後續 backend 保留空間。
- **Consequence:** 本計劃不做資料搬遷、雙寫或 ref rename。

### ADR-ACF-06：finalize deadline 由 policy 注入，pending 可重放

- **Status:** Accepted
- **Decision:** coordinator 接收絕對 deadline 與 provider policy。deadline 前可同步完成；耗盡時只允許兩種結果：`complete`，或 durable `pending` + sanitized reason + stable replay key。不得標 stopped/complete 後丟失 checkpoint；不得無界 retry。
- **Consequence:** Codex 3 秒、OpenCode process-exit、Claude/Pi host deadline 由各 provider 計劃提供；ACF 只交付共同機制。

### ADR-ACF-07：live/import 共用 service，入口語義仍分離

- **Status:** Accepted
- **Decision:** live hook 與 historical import 共用 snapshot/catalog/checkpoint service；import identity/consent/lease/coverage claim 保持 import entry 擁有，live 的 unknown-event/host-response 保持 hook entry 擁有。
- **Consequence:** coordinator 不吞併 consent 或 provider installer；只統一資料寫入與恢復語義。

### ADR-ACF-08：provider 計劃採用門

- **Status:** Accepted
- **Decision:** ACF-09 handoff 完成前，provider 計劃只有明列的 audit/spike/fixture 可以先行。完成後，provider 卡開工必須以 architecture guard 證明：adapter/parser/projector 不直接寫 SQL/ref；shared runtime 不增加 provider-name match branch。
- **Consequence:** 若某 provider 需要共用 contract 新能力，先回本計劃新增/修訂 ACF 卡，不在 provider plan 私建平行 seam。

## 全局工程約束

- **GC-ACF-01 單一 event:** canonical event 只能是 `LifecycleEvent`（可向後相容地擴充）；禁止新增平行 event enum/wire。
- **GC-ACF-02 單一 transcript source:** 所有 provider path/bytes 必須經 `TranscriptSource` 或其不可偽造的新 variant；禁止 path reopen 與任意 `Vec<u8>` 冒充授權 raw。
- **GC-ACF-03 redaction-first durable sink:** 普通 checkpoint/catalog/event sink 只接受 `RedactedBytes`/安全投影；raw 只存在於 bounded local scope。
- **GC-ACF-04 scope-first mutation:** catalog/checkpoint mutation 在任何 side effect 前驗證 `CaptureScope` 與 workspace fence。
- **GC-ACF-05 idempotency key:** session identity = `(repo_id, worktree_id, workspace_id/fence, agent_kind, provider_session_id)`；event/action identity 使用 stable event id/replay key；不得以 timestamp/隨機 UUID 避開 conflict。
- **GC-ACF-06 bounded input/state:** hook stdin 1 MiB、transcript 16 MiB 與既有 bounded arrays 是上限基線；調高必須有獨立容量證據。
- **GC-ACF-07 no silent success:** validation/store/finalize 失敗不得被 `installed=true`、`state=stopped` 或 exit 0 掩蓋；host 要求 fail-open 時也必須留下 sanitized durable/diagnostic evidence。
- **GC-ACF-08 no provider branches in coordinator:** coordinator 只按 capability/policy/action 分派，不可 `match AgentKind::Codex/OpenCode/...`。
- **GC-ACF-09 no new schema:** 本計劃各卡預設 `Migration and rollback=N/A`；需要 schema 時停卡、修訂並按 GC-13 新增 migration task。
- **GC-ACF-10 tests:** 每卡至少有 reducer/store failure path 與既有 provider regression；test fn 名稱在 Verification 標 `(new)`。
- **GC-ACF-11 docs:** internal architecture 變更同步 `docs/development/tracing/agent.md`；若公開 agent 行為漂移，該卡必須同步 EN/zh/網站，而非以「internal refactor」豁免。
- **GC-ACF-12 精確暫存:** 每卡先 `libra status --short --branch`，只 `libra add` 該卡 I/R 集；禁止 `commit -a`，不得混入當時任何其它計劃、Cargo/config/vault 或測試 fixture 改動。
- **GC-ACF-13 review:** 成稿及每次規範性修訂後執行 Claude 唯讀 review；P0/P1/P2 全部關閉並取得字面 `VERDICT: PASS` 才可開工。
