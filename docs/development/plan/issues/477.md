### Git 序列状态生命周期真值（2026-09-15 实测）

| 场景 | git 2.54 | libra 0.22.25 |
|---|---|---|
| 单提交 pick/revert 冲突 → `reset --hard` 或 `reset --mixed` | 状态清除；下一次 pick/revert 成功 | 状态残留，下一次被拒 |
| 单提交 pick 冲突 → 解决 + `add` → `commit` | 状态清除，`status` 干净 | `status` 仍报 `cherry-pick in progress` |
| 多提交 pick 冲突 → `reset --hard` | `status` 报 `Cherry-pick currently in progress`；`--continue` 只提交剩余项；新的多提交 pick 128 `cherry-pick is already in progress` | 状态保留；`--continue` 额外提交停止项（N3） |
| 多提交 pick 冲突 → 解决 + `commit` → `--continue` | 保留解决提交，只提交剩余项 | 额外重复提交停止项（N3） |
| merge 冲突 → `reset --hard/--mixed` | merge 状态清除 | 状态残留（N4） |
| rebase 冲突 → `reset --hard` | rebase 仍在进行，`--abort` 可用 | 一致 |
| `cherry-pick -n` 冲突 | 不产生序列状态，`--abort` 128 `no cherry-pick or revert in progress` | 一致（文案见 N2） |

### ADR-HF-02: 退出码模型

- **Status:** Accepted
- **Context:**
  - Git 对拒绝类错误（未合并分支删除、无可提交内容、空消息、模板未编辑）使用 exit 1，issue 条目 5 希望对齐。
  - Libra 稳定错误码表把 repo/conflict 类错误映射为 128，用法与无效目标映射为 129（`docs/error-codes.md:87-116`）。
  - [`issues/479.md`](479.md) ADR-PL-02 已决定保留文档化退出码；[`issues/484.md`](484.md) ADR-IA-02 只对「完整渲染后部分成功」使用 `silent_exit(1)`。
- **Decision:**
  1. **例外（issue 条目 5 明确要求）：** `branch -d/--delete` 的三类拒绝（未完全合并、分支不存在、分支被工作树检出）通过 `CliError::with_exit_code(1)` 以 exit 1 结束，稳定错误码保持原值（`LBR-REPO-003`、`LBR-CLI-003`、现有检出冲突码），文案对齐 Git（M-BRDEL）。先例为 `src/utils/error.rs:35` 注释所述「按命令匹配 Git 退出码」的 `with_exit_code` 覆盖。
  2. 其余拒绝类错误保留 128/129 与现有稳定错误码，包括：`commit` 无可提交、空消息、模板未编辑、`rebase -i` 的 `nothing to do` 与无效行，以及 HF-03/HF-11/HF-14 的新拒绝。
  3. 脚本通过三种方式区分「拒绝」与「仓库致命错误」：stderr 的 `Error-Code:` 行、`--json` error envelope 的 `error_code`，以及 `LIBRA_FINE_EXIT_CODES=1` 下的类别退出码（repo 3、conflict 4、cli 2）。各命令文档的退出状态小节写明这三种方式。
  4. HF-14 的拒绝使用既有 `LBR-UNSUPPORTED-001`（128），不新增稳定错误码。
  5. `with_exit_code(1)` 的覆盖在 `LIBRA_FINE_EXIT_CODES=1` 下同样生效，并写入 branch 文档的退出状态小节与 `docs/error-codes.md` 的说明段（不改稳定码表）。
- **Alternatives considered:** 全部拒绝类错误改为 exit 1——与 479/484 决策冲突，且 issue 只对 `branch -d` 提出要求，拒绝。为 `branch -d` 新增稳定错误码——命中 T-1，而 `with_exit_code` 已能在保留稳定码的同时对齐退出码，拒绝。
- **Consequences:** `branch -d` 拒绝的退出码 128/129 → 1 是公开行为变化，在 branch 文档与 `COMPATIBILITY.md:206` 写明；commit 等其余差异在 `COMPATIBILITY.md:209` 登记为有意差异。
- **Revisit when:** 稳定错误码表进行 major 调整。

### ADR-HF-03: 序列状态生命周期

- **Status:** Accepted
- **Context:** GAP-01..03；git `builtin/reset.c:542-543`、`branch.c:874-879`、`sequencer.c:3023-3058`；事实基线「Git 序列状态生命周期真值」。
- **Decision:**
  1. **reset 清除：** `reset` 成功完成且未给 pathspec 时（任意模式，含 `--merge/--keep`），按以下规则清除。清除位于成功路径末尾。
     - 清除 merge 进行中状态（`merge-state.json` 与 `SequenceKind::Merge` 行）。持有的 autostash 按既有提升逻辑存入 stash 列表并在 stderr 说明，对应 Git `save_autostash_ref`。
     - cherry-pick/revert 若为单提交操作，或停在序列最后一项，则清除其状态。
     - 多提交序列只标记「停止项已被外部结束」，保留剩余 todo。
     - rebase、am、bisect 状态不动。
  2. **commit 清除：** 非 `--dry-run` 的 `commit` 成功更新 HEAD 后，对 cherry-pick/revert 执行与第 1 条相同的清除与标记规则。
  3. **`--continue` 语义：** 多提交序列在「停止项已被外部结束」时执行 `--continue`，不再提交停止项，直接处理剩余 todo。
     - 若此时索引与 HEAD 不同，行为以 M-CONT C4 的 git 实跑为准写回本 ADR。
     - 「停止项已被外部结束」优先复用 `SequenceState` 既有字段表达（如清空 `current_oid`）。若必须新增列，按 GC-13 走 `sql/migrations/` 并先按 G-09 拆卡。
  4. **有意差异：** Git 允许在多提交序列进行中启动单提交 pick（N6），Libra 保持 `ensure_none_in_progress` 对称互斥。
  5. **失败处理：** 清除动作失败时，reset/commit 本身不回滚，只输出 warning，并提示 `libra cherry-pick --quit` / `libra merge --abort` 等收尾命令。
- **Alternatives considered:** 在 reset/commit 中直接删除侧车文件——绕过 sequencer 单一事实源与 GC 根登记，拒绝。reset 清除全部序列（含多提交）——丢失剩余 todo，与 Git 不符，拒绝。
- **Consequences:** HF-01 命中 T-1（共享 sequencer）；HF-02 依赖 HF-01 写入的标记。
- **Revisit when:** 统一 sequence_state 模型引入 todo 编辑（D16）。

### ADR-HF-04: 未合并索引上的 cherry-pick/revert

- **Status:** Accepted
- **Context:** N1、N2；git `sequencer.c:2306-2314`。
- **Decision:**
  - cherry-pick 与 revert 的所有开始路径（含 `-n`、多提交、`--ff`）在任何写入前检查索引。存在未合并条目时，返回 `LBR-CONFLICT-001`（128）并附 hint：列出冲突路径（最多 10 条），提示解决后 `libra add` 或 `libra reset`。

- **Consequences:** 以前在未合并索引上「成功」的调用改为失败，属于修复数据安全缺陷；文档登记。

- **Context:** GAP-05；git `builtin/merge.c:825-826`、`sequencer.c:484-499`；`plan-20260903.md:1238`。
- **Decision:**
  1. **merge：** 我方 `HEAD`；对方为用户在命令行给出的合并目标原文（`side`、`refs/heads/side`、完整 hash 原样保留）。目标由 `merge --continue` 重建时，从 `merge-state.json` 读取已保存的原文，不重新缩写。
  2. **cherry-pick：** 我方 `HEAD`；对方 `<abbrev7> (<subject>)`。
  3. **revert：** 我方 `HEAD`；对方 `parent of <abbrev7> (<subject>)`。
  4. **共同约束：** 整文件冲突与 diff3 base 标签按 M-LABEL L7/L8 实跑写回本 ADR。标签生成集中在一个 helper 中，merge rename 临时名的分支标签使用同一来源。
  5. **范围外：** `pull` 标签不变（DEFER-06）。
- **Alternatives considered:** merge 统一写分支短名——丢失 `refs/heads/side` 与 hash 写法的可区分性，与 Git 不符，拒绝。
- **Consequences:** 冲突文件内容是可观察输出，merge/cherry-pick/revert 文档写明；rerere 以规范化内容为键，不受影响（M-LABEL L9 验证）。
- **Revisit when:** 支持 `merge.conflictStyle` 以外的标签自定义。

### ADR-HF-08: 分支 upstream 指定与创建跟踪

- **Status:** Accepted
- **Context:** GAP-08/09；git `builtin/branch.c:997`、`:1003`、`:1220-1242`，`branch.c:91-125`；`t3200:849-872`、`:1005-1063`。
- **Decision:**
  1. **分支参数：** `-u/--set-upstream-to <upstream> [<branch>]`：`<branch>` 缺省为当前分支，超过一个参数为用法错误。
  2. **upstream 解析顺序：**
     - 若 `<upstream>` 形如 `<remote>/<branch>`，且 `<remote>` 已配置、`refs/remotes/<remote>/<branch>` 存在，则写 `remote=<remote>`、`merge=refs/heads/<branch>`；
     - 否则若 `refs/heads/<upstream>` 存在，则写 `remote=.`、`merge=refs/heads/<upstream>`；
     - 否则报错（文案与退出码按 M-UPSTREAM P6）。
  3. **创建时跟踪：** `-t/--track[=direct|inherit]`：`direct` 按第 2 条解析起点；`inherit` 复制起点分支的 upstream 配置。`--no-track` 不写配置。起点不是分支时按 M-TRACK T6。
  4. **读取方：** `branch -vv`、`status` 的 ahead/behind 能处理 `remote=.`。`pull/push/fetch` 遇到 `remote=.` 时 fail-closed 并给出说明（DEFER-08）。
  5. **不支持：** `branch.autoSetupMerge` 等自动跟踪配置（DEFER-07）。
- **Alternatives considered:** 只接受 `remote/branch`——与 Git 和 `t3200` 用例不符，拒绝。
- **Consequences:** HF-07 先落地解析与读取方，HF-08 复用。
- **Revisit when:** DEFER-08 排期。

### ADR-HF-15: 部分重开 D15 与 patch mode 引擎

- **Status:** Accepted
- **Context:** #477 评论 TC-0038..TC-0042 与条目 16 要求 `add -p`、`reset -p` 可用。D15 的重启条件是「可测试的 hunk 编辑模型、JSON/机器输出边界、端到端回归」（`_compatibility.md:180-184`）；本 ADR 与 M-HUNK、M-PATCH 逐条满足这三项。git 参照 `add-patch.c:262`、`:538`、`:1015-1051`、`:2040`。
- **Decision:**
  1. **范围：** 重开 D15 中的 `add -p/--patch` 与 `reset -p/--patch`；其余 patch mode 入口维持延后（DEFER-01，HF-14 诊断）。
  2. **引擎位置：** 新增内部模块 `src/internal/patch_mode/`，包含三部分：
     - 模型：`FileDiff{path, header, mode_change, added, deleted, binary, hunks}`、`Hunk{old/new range, lines, use: Undecided|Skip|Use, splittable_into}`；
     - 纯函数：解析、拆分、编辑后重算、重组补丁；
     - 模式表：`Stage`（索引 → 工作树）、`ResetHead`（撤销暂存，反向应用到索引）、`ResetNotHead`（把目标树内容应用到索引）。
  3. **diff 来源：** hunk 由 Libra 既有 Git 兼容 unified diff 生成（3 行上下文，与 `libra diff` 同一算法与 `diff.algorithm` 配置），不另写 diff 算法。M-HUNK H1 以 git 2.54 输出逐字节校验。
  4. **应用：** 选中 hunk 重组为补丁文本，经 `apply.rs` 的 section 应用逻辑作用于索引 blob（`src/command/apply.rs:630`），写入新 blob 与索引条目；patch mode 从不修改工作树。
  5. **写入时机：** 所有决定在会话结束（正常结束、`q`、EOF）时一次性原子写入索引。与 Git「自动前进模式下离开文件即应用」的差异只在进程被强杀时可观察，登记为有意差异，换取崩溃时索引不半更新。
  6. **机器输出边界：** `--json`、`--machine` 与 `-p` 组合为用法错误（129，`LBR-CLI-002`）；`--dry-run` 同理；patch mode 结束后不输出 JSON。
  7. **公开节奏：** 在 HF-19 完成 `s`/`e` 之前，`-p/--patch` 与 `--[no-]auto-advance` 以 `hide = true` 注册，文档与 `COMPATIBILITY.md` 不宣称支持，避免提示字母与 Git 不一致的中间版本被当作完整实现。HF-19 取消隐藏并同步文档；`reset -p`（HF-20）在 HF-19 之后直接公开。
  8. **操作日志：** 一次 patch mode 会话按一次索引变更记录，与 `add`/`reset` 的既有分类一致。
- **Alternatives considered:** 调用系统 git——违背仓库约定，拒绝。每个 hunk 立即写索引——崩溃时留下部分暂存且写放大，拒绝。先开放不含 `s`/`e` 的 `add -p`——提示字母与 Git 不一致，拒绝。
- **Consequences:** D15 在 HF-19/HF-20 后拆分登记；引擎被 `add` 与 `reset` 共用，HF-15 命中 T-1。
- **Revisit when:** DEFER-01 排期（`checkout/restore/stash -p` 可复用模式表）。

### ADR-HF-16: patch mode 会话输入输出

- **Status:** Accepted
- **Context:** M-PATCH、M-ADVANCE 断言的是 stdout 逐字节内容；git 参照 `add-patch.c:48-138`、`:420-428`、`:1362-1373`、`:1534-1548`、`:1607-2000`。
- **Decision:**
  1. **提示文本：** `(i/n) ` + 模式提示（`Stage this hunk` / `Stage deletion` / `Stage addition` / `Stage mode change`；reset 的 `Unstage ...` 与 `Apply ... to index`）+ `(was: y|n)` + `[y,n,q,a,d<可用字母>,?]? `。可用字母按 Git 顺序拼接 `k,K,j,J,g,/,s,e,>,<,p,P`，每个字母只在可用时出现。
  2. **错误与帮助：** 错误行写到 stdout，文案与 Git 相同（`Only one letter is expected, got '%s'`、`Unknown command '%s' (use '?' for help)`、`No other hunk`、`No other undecided hunk`、`Sorry, cannot split this hunk` 等）。`?` 输出模式帮助加上按可用字母过滤的帮助余项；全部决定时追加 `HUNKS SUMMARY - Hunks: %d, USE: %d, SKIP: %d`。
  3. **输入：** TTY 与非 TTY 一律按行读取 stdin，去掉行尾换行；EOF 等同 `q`；除 `g`、`/` 外多字符输入报错；`g`、`/` 的参数可同行或在后续提示行给出。
  4. **渲染：** 文件头为 `diff --git`、`index <abbrev7>..<abbrev7> <mode>`、mode 行与 `---`/`+++`；hunk 为 `@@` 头与内容。非 TTY 或 `--color=never` 时无颜色（TTY 着色见 DEFER-10）。`p` 重新打印当前 hunk；`P` 按 `LIBRA_PAGER` 策略分页，非 TTY 时等同 `p`。
  5. **文件集合：** 按路径字节序；只含 pathspec 内已跟踪条目；未跟踪文件不出现；二进制文件跳过。无文件时输出 `No changes.`，全部为二进制时输出 `Only binary files changed.`，均 exit 0。
  6. **退出码：** 正常结束、`q`、EOF 为 0；索引写入失败为 128；参数与目标错误按 ADR-HF-02。
- **Alternatives considered:** 实现 `interactive.singleKey` 原始按键读取——非 TTY 测试不需要，且跨平台终端处理成本高，登记 DEFER-10。
- **Consequences:** 提示与帮助文本以常量表集中定义，并由单元测试对照 git 2.54 原文。
- **Revisit when:** 需要本地化提示文本。

### ADR-HF-17: `--[no-]auto-advance` 与跨文件导航

- **Status:** Accepted
- **Context:** TC-0038..TC-0041；git `add-patch.c:1660-1675`、`:1726-1735`、`:1810-1830`、`:2029-2031`；`builtin/add.c:502-503`；`builtin/reset.c:448-449`。
- **Decision:**
  1. **参数：** `add` 与 `reset` 新增 `--auto-advance` / `--no-auto-advance`，默认自动前进，后者生效。
  2. **缺少 patch mode：** `add` 报 128 `fatal: the option '--no-auto-advance' requires '--interactive/--patch'`；`reset` 报 128 `... requires '--patch'`；均零写入。

- **Consequences:** 会话状态机以 Git 状态转移为准，单元测试覆盖 `add-patch.c:1607-1830` 的每个分支。
- **Revisit when:** 无。

### ADR-HF-18: `s` 拆分与 `e` 手工编辑

### ADR-HF-19: 部分重开 D16，交互式 rebase 的 todo 模型

- **Status:** Accepted
- **Context:**
  - 条目 4、13 与 `t3400/t3404` 缺口要求 `rebase -i` 可用。
  - D16 的重启条件是「sequencer 状态模型、错误恢复和非 TTY/Agent 驱动协议」（`_compatibility.md:186-190`）。统一 `sequence_state` 已落地；`GIT_SEQUENCE_EDITOR` 即非 TTY 驱动协议。
  - Libra 现有 `RebaseState`（SQLite）只表达「提交 + pick/fixup/squash/amend」，`exec` 由侧车 `rebase-aux.json` 保存（`src/command/rebase.rs:45-90`）。
- **Decision:**
  1. **范围：** 重开 D16 中的 `rebase -i/--interactive` 与 `--edit-todo`。`-r/--rebase-merges`、`label/reset/merge/update-ref` 行、`-i --update-refs`、`rebase.missingCommitsCheck`、`rebase.abbreviateCommands`、`rebase.instructionFormat` 维持延后（DEFER-02，HF-14 诊断）。
  2. **todo 指令模型：** `TodoInstruction{Pick, Reword, Edit, Squash, Fixup{flag: None|C|c}, Exec(cmd), Break, Drop}(commit?)`，支持全称与缩写，`#` 注释与空行忽略。解析错误逐行报告 `invalid command '<cmd>'` 与 `invalid line <n>: <line>`。
  3. **持久化：**
     - 完整指令列表保存在 `rebase-aux.json` 新字段 `todo_instructions` 与 `done_instructions`。
     - SQLite `todo`/`todo_actions` 继续保存待处理提交与可表达的动作，供 GC 根与旧逻辑使用。
     - 新字段为 additive 字段，不改 schema。
     - 旧版本 Libra 遇到交互式进行中状态时 fail-closed（M-TODO T9），降级前需 `--continue` 完成或 `--abort`。
  4. **序列编辑器：** 新增 `editor::resolve_sequence_editor`，顺序为 `GIT_SEQUENCE_EDITOR` → `sequence.editor` → `resolve_editor` 链。缓冲区写入 `<gitdir>/rebase-merge/git-rebase-todo`，编辑器以非零退出时中止且零写入。
  5. **todo 文本：** 首次生成时为 `pick <abbrev> # <subject>` 行、空行、`# Rebase <onto>..<head> onto <onto> (N commands)` 与帮助注释；`--edit-todo` 只含剩余指令并附进行中提示（I1、I7）。帮助注释中 `l/t/m/u` 四项因 DEFER-02 不输出，这一差异登记在本 ADR。
  6. **空 todo 与无效行：**
     - 空 todo：报 `error: nothing to do` 并不创建状态（ADR-HF-02：128 + `LBR-REPO-003`）。
     - 无效行：创建进行中状态、HEAD 置于 onto，输出修复提示，允许 `--edit-todo` 后 `--continue` 或 `--abort`（I9）。
  7. **公开节奏：** HF-21..HF-23 期间 `-i/--interactive` 与 `--edit-todo` 以 `hide = true` 注册，文档不宣称支持；HF-24 取消隐藏并修订 D16。
- **Alternatives considered:** 为指令新增 SQLite 列——需要迁移且旧版本无法安全忽略，拒绝。只支持 `pick/drop/squash/fixup`——`reword/edit/exec/break` 为 `t3404` 基础用例，无法关闭条目 13，拒绝。
- **Consequences:** GC 根收集需覆盖 `todo_instructions` 中的提交 id（ER-HF-06）。
- **Revisit when:** DEFER-02 排期。

### ADR-HF-20: 交互式 rebase 指令语义

- **Status:** Accepted
- **Context:** Git 交互式 rebase 真值 I1–I13；git `sequencer.c:1886-1899`、`:3886`、`:3947`、`:4968`、`:5050`；`builtin/rebase.c:1602-1607`。
- **Decision:**
  1. **`pick/drop`：** 复用既有重放引擎；删除行或 `drop` 丢弃提交，与默认 `missingCommitsCheck=ignore` 一致。
  2. **`squash/fixup`：**
     - 复用既有折叠逻辑。`squash` 消息由编辑器决定，编辑器为 `true` 时保留拼接消息；`fixup` 丢弃自身消息；`fixup -C` 采用该提交消息；`fixup -c` 在此基础上打开编辑器。
     - 第一条指令为 `squash/fixup` 时报错并零写入。
  3. **`reword`：** 重放后以普通编辑器编辑消息；编辑结果为空时中止该步并停止。
  4. **`edit`：** 重放后停止，输出 `Stopped at <abbrev>...  <subject>` 与 amend 说明。`--continue` 接受 `commit --amend` 结果或工作树中已暂存的改动。
  5. **`break`：** 停止并输出 `Stopped at <abbrev> (<subject>)`。
  6. **`exec`：** 输出 `Executing: <cmd>`，在既有 rebase exec 沙箱中运行（工作区可写、禁网，沿用 `src/command/rebase.rs:2317` 的有意差异）。失败时输出 `warning: execution failed: <cmd>` 并停止，`--continue` 继续剩余项。
  7. **组合：** `-i` 下 `--autosquash`（含 `rebase.autosquash=true`）在生成 todo 时重排并改写为 `fixup/squash`；`--exec` 在每个 pick 后插入 `exec` 行；`--root` 从根提交生成 todo；`--autostash` 语义与非交互一致。
  8. **冲突：** 冲突停止与 `--continue/--skip/--abort` 复用非交互路径与 HF-01..HF-03 的状态规则。
- **Alternatives considered:** `exec` 在交互模式下不走沙箱——与既有 `--exec` 的安全边界不一致，拒绝。
- **Consequences:** `status` 继续只显示单行进行中提示（明细见 DEFER-11）。
- **Revisit when:** exec 沙箱策略调整。
