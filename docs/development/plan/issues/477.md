## 文档职责

issue #477 是一次批量对照，写于 libra 0.22.5。本计划在 libra 0.22.25 与 git 2.54.0 上分三轮并排实跑，逐条复核 16 个条目和 1 条评论，结论分三类：

- **已修复或断言不成立：**
  - 条目 8 `switch --detach <rev>` 已能分离 HEAD；
  - 条目 4 `commit --squash` 与条目 16 `reset --merge/--keep` 已存在；
  - 条目 2 与 Git 实测相反：Git 同样拒绝未编辑的模板；
  - 条目 3 与 `-s` 无关，真实缺陷是「无暂存改动」时的错误文案。
- **确认的缺口：**
  - `commit --allow-empty-message`；
  - `branch` 的 upstream 指定与 `--track`；
  - `tag -a`；
  - 冲突标记标签；
  - `rebase --autosquash` 在无需变基时空转；
  - `rebase --root`；
  - 交互式参数（D15/D16）缺少可用诊断。
- **issue 未列出、风险更高的新发现：**
  - 单提交 cherry-pick/revert 停在冲突后，`reset` 或结束性 `commit` 不清除进行中状态，后续 pick/revert 被卡住；merge 状态也不随 `reset` 清除。这正是条目 14 所说「卡死」的真实触发路径。
  - 多提交序列在外部结束当前项后，`--continue` 会重新提交已放弃的停止项。
  - cherry-pick/revert 在未合并索引上照常执行：`cherry-pick <提交>` 生成的提交删除了冲突路径；`revert --no-commit` 覆盖未解决的冲突。
  - 裸 `checkout --detach` 是静默空操作。

本计划按风险排序交付 14 张卡：
1. **Phase 1（状态与数据安全）：** HF-03、HF-01、HF-02。
2. **Phase 2（冲突呈现与诊断）：** HF-04、HF-05、HF-14。
3. **Phase 3（参数补齐）：** HF-06..HF-13。

交互式 patch mode 与交互式 rebase 仍按 D15/D16 拒绝，本计划只交付稳定诊断，并登记 DEFER。

本文只规划任务，不宣称实现完成。落地时每个任务都必须先刷新源码锚点，再按任务卡验收。

### Git 序列状态生命周期真值（2026-09-15 实测）

| 场景 | git 2.54 | libra 0.22.25 |
|---|---|---|
| 单提交 pick/revert 冲突 → `reset --hard` 或 `reset --mixed` | 状态清除；下一次 pick/revert 成功 | 状态残留，下一次被拒 |
| 单提交 pick 冲突 → 解决 + `add` → `commit` | 状态清除，`status` 干净 | `status` 仍报 `cherry-pick in progress` |
| 多提交 pick 冲突 → `reset --hard` | `status` 报 `Cherry-pick currently in progress`；`--continue` 只提交剩余项；新的多提交 pick 128 `cherry-pick is already in progress` | 状态保留；`--continue` 额外提交停止项（N3） |
| 多提交 pick 冲突 → 解决 + `commit` → `--continue` | 保留解决提交，只提交剩余项 | 额外重复提交停止项（N3） |
| merge 冲突 → `reset --hard/--mixed` | merge 状态清除 | 状态残留（N4） |
| rebase 冲突 → `reset --hard` | rebase 仍在进行，`--abort` 可用 | 一致 |
| `cherry-pick -n` 冲突 | 不产生序列状态，`--abort` 128 `no cherry-pick or revert in progress` | 一致（文案见 N2） |

### ADR-HF-02: 退出码模型

- **Status:** Accepted
- **Context:**
  - Git 对拒绝类错误（未合并分支删除、无可提交内容、空消息、模板未编辑）使用 exit 1，issue 条目 5 希望对齐。
  - Libra 稳定错误码表把 repo/conflict 类错误映射为 128，用法与无效目标映射为 129（`docs/error-codes.md:87-116`）。
  - [`issues/479.md`](479.md) ADR-PL-02 已决定保留文档化退出码；[`issues/484.md`](484.md) ADR-IA-02 只对「完整渲染后部分成功」使用 `silent_exit(1)`。
- **Decision:**
  1. 本计划所有拒绝类错误保留 128/129 与现有稳定错误码，包括：`branch -d` 未合并、`branch -d` 不存在、`commit` 无可提交、空消息、模板未编辑，以及 HF-03/HF-11/HF-14 的新拒绝。
  2. 脚本通过三种方式区分「拒绝」与「仓库致命错误」：stderr 的 `Error-Code:` 行、`--json` error envelope 的 `error_code`，以及 `LIBRA_FINE_EXIT_CODES=1` 下的类别退出码（repo 3、conflict 4、cli 2）。各命令文档的退出状态小节写明这三种方式。
  3. HF-14 的拒绝使用既有 `LBR-UNSUPPORTED-001`（128），不新增稳定错误码。
- **Alternatives considered:** 按命令逐个改为 exit 1——破坏已发布的稳定错误码契约，与 479/484 决策冲突，而上游 `test_must_fail` 只要求非零，拒绝。新增「refused」稳定错误码——命中 T-1，收益低于文档化区分方式，拒绝。
- **Consequences:** 退出码差异在 `COMPATIBILITY.md` 的 branch、commit 行登记为有意差异。
- **Revisit when:** 稳定错误码表进行 major 调整。

### ADR-HF-03: 序列状态生命周期

- **Status:** Accepted
- **Context:** GAP-01..03；git `builtin/reset.c:542-543`、`branch.c:874-879`、`sequencer.c:3023-3058`；事实基线「Git 序列状态生命周期真值」。
- **Decision:**
  1. **reset 清除：** `reset` 成功完成且未给 pathspec 时（任意模式，含 `--merge/--keep`），按以下规则清除。清除位于成功路径末尾。
     - 清除 merge 进行中状态（`merge-state.json` 与 `SequenceKind::Merge` 行）。持有的 autostash 按既有提升逻辑存入 stash 列表并在 stderr 说明，对应 Git `save_autostash_ref`。
     - cherry-pick/revert 若为单提交操作，或停在序列最后一项，则清除其状态。
     - 多提交序列只标记「停止项已被外部结束」，保留剩余 todo。
     - rebase、am、bisect 状态不动。
  2. **commit 清除：** 非 `--dry-run` 的 `commit` 成功更新 HEAD 后，对 cherry-pick/revert 执行与第 1 条相同的清除与标记规则。
  3. **`--continue` 语义：** 多提交序列在「停止项已被外部结束」时执行 `--continue`，不再提交停止项，直接处理剩余 todo。
     - 若此时索引与 HEAD 不同，行为以 M-CONT C4 的 git 实跑为准写回本 ADR。
     - 「停止项已被外部结束」优先复用 `SequenceState` 既有字段表达（如清空 `current_oid`）。若必须新增列，按 GC-13 走 `sql/migrations/` 并先按 G-09 拆卡。
  4. **有意差异：** Git 允许在多提交序列进行中启动单提交 pick（N6），Libra 保持 `ensure_none_in_progress` 对称互斥。
  5. **失败处理：** 清除动作失败时，reset/commit 本身不回滚，只输出 warning，并提示 `libra cherry-pick --quit` / `libra merge --abort` 等收尾命令。
- **Alternatives considered:** 在 reset/commit 中直接删除侧车文件——绕过 sequencer 单一事实源与 GC 根登记，拒绝。reset 清除全部序列（含多提交）——丢失剩余 todo，与 Git 不符，拒绝。
- **Consequences:** HF-01 命中 T-1（共享 sequencer）；HF-02 依赖 HF-01 写入的标记。
- **Revisit when:** 统一 sequence_state 模型引入 todo 编辑（D16）。

### ADR-HF-04: 未合并索引上的 cherry-pick/revert

- **Status:** Accepted
- **Context:** N1、N2；git `sequencer.c:2306-2314`。
- **Decision:**
  - cherry-pick 与 revert 的所有开始路径（含 `-n`、多提交、`--ff`）在任何写入前检查索引。存在未合并条目时，返回 `LBR-CONFLICT-001`（128）并附 hint：列出冲突路径（最多 10 条），提示解决后 `libra add` 或 `libra reset`。
  - 控制动词（`--continue/--skip/--abort/--quit`）不受该检查影响，保持现有语义。
  - 单提交 `-n` 冲突的文案不再提及 `multi-commit`，改为说明「`--no-commit` 冲突不产生可继续的序列，解决后 `libra add`，或以 `libra reset --hard` 放弃」。
- **Alternatives considered:** 只在 `-n` 路径检查——常规 pick 同样会覆盖未合并索引（Q6），拒绝。
- **Consequences:** 以前在未合并索引上「成功」的调用改为失败，属于修复数据安全缺陷；文档登记。
- **Revisit when:** 无。

### ADR-HF-05: 冲突标记标签

- **Status:** Accepted
- **Context:** GAP-05；git `builtin/merge.c:825-826`、`sequencer.c:484-499`；`plan-20260903.md:1238`。
- **Decision:**
  1. **merge：** 我方 `HEAD`；对方为用户在命令行给出的合并目标原文（`side`、`refs/heads/side`、完整 hash 原样保留）。目标由 `merge --continue` 重建时，从 `merge-state.json` 读取已保存的原文，不重新缩写。
  2. **cherry-pick：** 我方 `HEAD`；对方 `<abbrev7> (<subject>)`。
  3. **revert：** 我方 `HEAD`；对方 `parent of <abbrev7> (<subject>)`。
  4. **共同约束：** 整文件冲突与 diff3 base 标签按 M-LABEL L7/L8 实跑写回本 ADR。标签生成集中在一个 helper 中，merge rename 临时名的分支标签使用同一来源。
  5. **范围外：** `pull` 标签不变（DEFER-06）。
- **Alternatives considered:** merge 统一写分支短名——丢失 `refs/heads/side` 与 hash 写法的可区分性，与 Git 不符，拒绝。
- **Consequences:** 冲突文件内容是可观察输出，merge/cherry-pick/revert 文档写明；rerere 以规范化内容为键，不受影响（M-LABEL L9 验证）。
- **Revisit when:** 支持 `merge.conflictStyle` 以外的标签自定义。

### ADR-HF-08: 分支 upstream 指定与创建跟踪

- **Status:** Accepted
- **Context:** GAP-08/09；git `builtin/branch.c:997`、`:1003`、`:1220-1242`，`branch.c:91-125`；`t3200:849-872`、`:1005-1063`。
- **Decision:**
  1. **分支参数：** `-u/--set-upstream-to <upstream> [<branch>]`：`<branch>` 缺省为当前分支，超过一个参数为用法错误。
  2. **upstream 解析顺序：**
     - 若 `<upstream>` 形如 `<remote>/<branch>`，且 `<remote>` 已配置、`refs/remotes/<remote>/<branch>` 存在，则写 `remote=<remote>`、`merge=refs/heads/<branch>`；
     - 否则若 `refs/heads/<upstream>` 存在，则写 `remote=.`、`merge=refs/heads/<upstream>`；
     - 否则报错（文案与退出码按 M-UPSTREAM P6）。
  3. **创建时跟踪：** `-t/--track[=direct|inherit]`：`direct` 按第 2 条解析起点；`inherit` 复制起点分支的 upstream 配置。`--no-track` 不写配置。起点不是分支时按 M-TRACK T6。
  4. **读取方：** `branch -vv`、`status` 的 ahead/behind 能处理 `remote=.`。`pull/push/fetch` 遇到 `remote=.` 时 fail-closed 并给出说明（DEFER-08）。
  5. **不支持：** `branch.autoSetupMerge` 等自动跟踪配置（DEFER-07）。
- **Alternatives considered:** 只接受 `remote/branch`——与 Git 和 `t3200` 用例不符，拒绝。
- **Consequences:** HF-07 先落地解析与读取方，HF-08 复用。
- **Revisit when:** DEFER-08 排期。

### ADR-HF-12: `rebase --autosquash` / `--no-autosquash`

### ADR-HF-13: `rebase --root`

- **Status:** Accepted
- **Context:** GAP-14；git `builtin/rebase.c:1243`、`:1564-1565`、`:1650-1682`。
- **Decision:**
  - `rebase --root [--onto <newbase>] [<branch>]`：重放 `<branch>`（缺省当前分支）从根提交起的全部提交。
    - 无 `--onto` 时，根提交重放为无父提交，未改变的 pick 保持原 hash；
    - 有 `--onto` 时，全部提交重放到 `<newbase>` 上。
  - 可与 `--autosquash`、`--exec`、`--autostash` 组合。
  - 与 `<upstream>` 位置参数同用为用法错误。
  - 冲突停止、`--continue/--skip/--abort` 复用既有序列状态。
- **Alternatives considered:** 延后——issue 明确列出，且非交互重放引擎已具备，拒绝。
- **Consequences:** HF-13 依赖 HF-12 对捷径逻辑的调整。
- **Revisit when:** 无。

| 未合并索引检查读取索引失败 | 无写入 | 返回索引读取错误 | 跳过检查继续执行 |
| `--continue` 读到损坏的外部结束标记 | 序列状态原样 | fail-closed 报 `LBR-REPO-002`，提示 `--abort` | 重复提交停止项 |
| 发布步 `gh release create` 失败 | 已推送的 `main` 提交 | 按 ER-09 记录，下一窗口补 tag/release | blind retry；只推 `main` 就宣称已发布 |
| D 组 `release.yml` 失败 | 已存在的 tag | 前滚修复，发新 patch | 回退已推送提交或删除已发布 artifact |
