## 文档职责

本计划解决 issue #498（tag 系列）：`libra tag <name> <commit>` 不接受显式目标提交的位置参数（相对 Git 而言）。Git 的 `git tag <name> <commit>` 在指定目标提交上建立标签；libra 在 0.22.33 时此参数不被接受，导致 `merge refs/tags/<tag>` / `merge <tag>` 等依赖 tag 目标的场景（DEFER-13 的撤回发现）失败。目标是让 `tag <name> <commit>` 接受目标提交并建 tag，从而解除 DEFER-13 所依赖的 tag 目标缺口。

本文只规划任务，不宣称实现完成。落地时每个任务都必须先刷新源码锚点，再按任务卡验收。

### 适用范围

- `libra tag <name> <commit>`（位置参数目标提交）的解析与建 tag 行为。
- 轻量 tag 与带目标的 tag；`--points-at`、`--create-reflog` 等 tag 选项的交互。
- `merge <tag>` / `merge refs/tags/<tag>` 依赖 tag 目标的场景。
- 同步：tag 文档、`COMPATIBILITY.md`、`../libra-backend` 文档、compat 守卫。

### 非目标

- 历史改写家族其余命令（#477 已收口的 commit/branch/rebase/cherry-pick 等由 #477b 后续承接）。
- 注签（`-a`/`-s`）、`tag -a` 的独立行为（如确与目标参数交互才纳入）。
- `tag --contains`/`--merged` 等其它缺口（#533）。

### 成功定义

- `libra tag <name> <commit>` 在指定目标提交上建 tag，`git rev-parse <name>` 解析到正确提交。
- `merge refs/tags/<tag>` 与 `merge <tag>`（DEFER-13 的撤回场景）不再因 tag 未创建而失败。
- 相关 Git 上游场景移植并有回归守卫；`--points-at` 等选项交互正常。
- 任务卡取得 C 组发布与 D 组证据，收口门全绿后才标记完成。
